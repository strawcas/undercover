# Tech stack

- `backend/`: FastAPI and SQLite. Every API operation has an `operation_id`, a one-line docstring and no optional inputs. Paying a claim is a separate operation that takes the amount.
- `agent/`: LangChain's `create_agent` for a planning queue agent and fresh per-claim helpers. Keep `run(claim_id, thread_id)` for claim work; `run_queue` coordinates full, capped or named scopes through HTTP tools. Backend-owned SQLite runs, attempts, to-dos and exact section evidence enforce the workload and financial boundaries. Neither agent reads business files or SQLite directly. Middleware bounds model/tool calls, retries transient provider failures and checks completion. `MODEL_PROVIDER` selects `openrouter` (the default, using `ChatOpenAI`) or `ollama` (using `langchain-ollama`'s `ChatOllama`). OpenRouter uses `deepseek/deepseek-v4.1-flash` with low reasoning effort by default, including when selected explicitly. `MODEL_NAME` overrides it, such as `openrouter/free`; other models are not forced to accept the default's reasoning setting. Ollama requires `MODEL_NAME` to name a downloaded model that supports tool calling. `OLLAMA_BASE_URL` defaults to `http://localhost:11434`.
- `dashboard/`: React, Vite, Tailwind CSS and strict TypeScript. Read-only polling shows run progress, claim activity, versioned section evidence and both instruction sets; handler sign-off and payment remain separate actions.
- `e2e/`: Playwright tests.
- `data/`: the business data the backend starts from, including indexed policy wording and claims manual sections. Deterministic section search needs no vector database. The agent never sees `data/evals/`, which holds the answer key.

Python 3.12 with uv, all in the root `pyproject.toml`. Node 26. Configure the provider and model in the root `.env`. OpenRouter requires `OPENROUTER_API_KEY`; local Ollama requires no API key. Ollama requests use 16,384 context tokens by default; `OLLAMA_NUM_CTX` overrides this with a positive integer to fit policy evidence, tool history and available memory.

`UNDERCOVER_MAX_CLAIMS` optionally caps each startup or terminal run's distinct claims. The CLI accepts `--max-claims N` or `--claim-id ID`; an explicit cap overrides the environment, and named mode ignores it. Runs snapshot eligibility once. SQLite preserves results and failures, but model conversations do not resume after a restart. Each assessment has a ten-minute deadline, forty model calls and eighty tool calls; model requests time out after 120 seconds. Transient transport/provider calls retry at most twice with 0.25/0.5-second backoff; SDK retries are disabled. Financial writes require read-back reconciliation before any retry.
