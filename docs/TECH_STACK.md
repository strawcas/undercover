# Tech stack

- `backend/`: FastAPI and SQLAlchemy Core, using Supabase Postgres when `DATABASE_URL` is present and SQLite otherwise. Shared table definitions, bound statements and stable positions keep one business-query surface. Every API operation has an `operation_id`, a one-line docstring and required inputs. Money uses Decimal and integer cents. The payout calculator reads stored policy/plan/company settings; decisions and simulated payments remain separate financial operations.
- `agent/`: a planning queue on LangChain `create_agent`, plus a synchronous hand-written LangGraph claim graph. Named nodes reason, call claim/reference/payout tools, save a structured decision, wait with `interrupt()` when required and pay every approval. `run(claim_id, thread_id)` remains the shared claim workflow; `run_queue` reconstructs finite scopes from backend records and explicitly checks completion. The service owns one sequential worker shared by terminal commands and sign-off notifications.
- `dashboard/`: React, Vite, Tailwind CSS and strict TypeScript. Polling reads progress, claim activity, versioned evidence and both instruction sets. Signing off saves attribution and shows In progress until graph payment. Payment displays the saved handler/time. Manual payment remains available only for claims without an agent-owned pending payment.
- `e2e/`: Playwright with a temporary SQLite backend, scripted models and a separate notification stand-in on port 8003.
- `data/`: the permitted seed records and indexed wording/manual sections. Deterministic section search needs no vector database. Agents never read business files directly or access `data/evals/`.

Python 3.12 with uv and the root `pyproject.toml`; Node 26. Development and terminal entry points explicitly load `.env` without overriding terminal variables. Imports and test app factories do not load it. A configured Postgres failure is visible and never falls back to SQLite. Switching targets preserves the previous SQLite file; automatic transfer of historical local work is outside this build.

## Persistence and ownership

Use the Supabase session pooler with synchronous psycopg on port 5432. Backend and graph connections set `search_path=undercover`; product tables and checkpointer tables stay in that schema. The backend uses at most four SQLAlchemy connections with no overflow. The agent uses one synchronous `PostgresSaver` pool of at most four, including its held service-ownership connection. Setup/reset processes also use at most four. The CLI and dashboard open no database connections.

Local mode and tests use the selected SQLite file for business records and synchronous `SqliteSaver` checkpoints. Every graph invocation uses `durability="sync"`. SQLite file locks and Postgres advisory locks exclude competing backend/agent owners and active reset. Short business transactions never span HTTP/model requests or human waits. Pools and owners close on shutdown.

Renewable attempt leases and execution IDs fence stale writers while preserving a resumed assessment's thread and attempt number. Queue generations fence an old coordinator after continuation. Interrupted queue scopes keep their snapshot, admitted IDs, cap and to-dos; a continuation finishes that scope without opening another snapshot. Completed summaries and their attempt views stay completion-time snapshots. Live claim/execution APIs show later sign-off and payment.

Matching financial repeats return the stored claim without new events; changed business fields are refused. Ambiguous responses require read-back reconciliation. Reset validates source records before transactionally clearing owned Postgres business/checkpoint data or replacing the selected SQLite file. It preserves unrelated schemas and requires backend and agent owners to be stopped.

## Service and models

`npm run dev` starts backend :8000, agent :8002 and dashboard :5173. `UNDERCOVER_AGENT` defaults to `http://127.0.0.1:8002`; `UNDERCOVER_BACKEND_URL` defaults to `http://localhost:8000`. Services start without admitting fresh work. `uv run -m agent` requests the eligible snapshot; `--cap N`, alias `--max-claims N`, and `--claim-id ID` select a finite scope. The old `UNDERCOVER_MAX_CLAIMS` setting is ignored.

The CLI attaches to matching local services or starts temporary backend/agent processes using Windows-compatible process spawning. Health headers identify the normalized database target by hash; the agent also identifies its service role. These identity checks are not authentication. Sign-off commits before a bounded background notification; failed delivery cannot undo it. Notifications re-read saved state and coalesce. Saved sign-offs receive priority at a safe claim boundary, and an explicit command recovers work missed while the service was unavailable.

After acquiring exclusive service ownership, startup reconciles a previous owner's running queue and active claim executions through the existing backend APIs. This also covers registration before the first checkpoint and held-claim continuation after a parent finishes. It suspends saved work without admitting claims or consuming failures; an explicit queue command or saved-sign-off notification then continues execution.

`MODEL_PROVIDER` selects OpenRouter through `ChatOpenAI` (default) or Ollama through `ChatOllama`. OpenRouter requires `OPENROUTER_API_KEY` and defaults to `deepseek/deepseek-v4.1-flash` with low reasoning effort. `MODEL_NAME` overrides it, including `openrouter/free`; other models are not forced to use that reasoning setting. Ollama needs a downloaded tool-calling `MODEL_NAME`, uses `OLLAMA_BASE_URL` (default `http://localhost:11434`, without `/v1`) and 16,384 context tokens, overridden by positive `OLLAMA_NUM_CTX`. Restart the agent service after changing its provider/model/database settings. Payment-only continuation constructs no model.

Each assessment has thirty durable model-request reservations, including structured decisions and provider retries, eighty tool calls and ten minutes of active-work allowance. Human waiting and process downtime do not consume that allowance. Model requests time out after 120 seconds. Transient requests retry at most twice with 0.25/0.5-second backoff; SDK retries are disabled. Queue middleware bounds its history and workload-scaled calls. Genuine undecided failures retry with a clean thread, up to two failed assessments; interruption preserves the existing attempt.

When `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY` are configured, claim graph callbacks use session `claim_id:thread_id` and claim/run/attempt metadata. `LANGFUSE_BASE_URL` selects the host. Resumptions retain the session. Trace initialization/export/flush and activity delivery are observational; failures emit safe diagnostic references and cannot undo business results. Tests disable exports and use stub models.
