## Running it

- `uv sync` and `npm install` install dependencies and hooks. `npm run seed` rebuilds the database selected by `.env`, including pristine evaluation sources and isolated handler labels. It resets the queue and clears runs, measurements, evaluation copies and the scoreboard. Reseed when moving from an earlier schema.
- `npm run dev` starts backend 8000, agent service 8002 and dashboard http://localhost:5173 with `.env`. The backend uses Supabase when DATABASE_URL is set, otherwise SQLite. The agent always needs Postgres for durable checkpoints. Both processes keep at most four database connections.
- Start a dispatch from the queue. Choose N from 1 to 25, default 3. The service accepts immediately and reserves one dispatch/evaluation slot; a second start gets 409. An unavailable service produces 503 and no run record.
- `uv run -m agent CLM-1001` still works one waiting claim. A claim id is required; queue mode and `--cap` are removed. The API address comes from the shell's UNDERCOVER_API (default localhost 8000); model/database/tracing configuration can come from `.env`.
- A held original claim can be signed off on its claim page. The service reserves the handoff even if the worker is still reaching its pause, resumes that same saved thread and pays it. If the service was away, the next dispatch resumes it.
- Start evaluations on `/scoreboard`: evaluation or held-out set, full 25 or tiny 5, N=1 to 25. They need no reseed and work fresh copies through the same graph. Copies never enter the queue or customer history, cannot be signed off and have their checkpoints removed after completion/recovery.

## Built

- Model-free LangGraph dispatcher: oldest waiting/in-progress claims, one Send per claim, additive results and max_concurrency=N, with no dispatcher saver or shared claim thread.
- Durable claim graph and unchanged seven tools/instructions. Each execution gets its own PostgresSaver on the shared four-connection process pool. Tools stay sequential within a claim.
- Transient model rate limits/timeouts retry up to three worker tries on the same saved attempt. Exhausted claims stay in progress for the next dispatch. Other pre-decision failures retry fresh in the same dispatch; two failed attempts leave the claim for a handler. Recorded decisions/payments are retained and backend row locks/idempotency prevent duplicates.
- Tokens and OpenRouter-reported cost are saved per received reply with claim/thread/run identity. Missing usage stays unavailable. Monotonic cumulative work slices include failed attempts and checkpoint preparation, exclude downtime/handler wait, and preserve the last confirmed duration after a kill. Run wall time is separate. Standalone work has null run identity; a later dispatch cannot change earlier run totals.
- Default `openai/gpt-6-luna` with low effort; every explicit MODEL_NAME uses no effort. Run records store the resolved configuration. Each Langfuse root keeps the claim/thread session and the current run id tag.
- Backend records build dispatch summaries and freeze completed outcomes. Polling uses batched outcomes/aggregates so query count stays fixed at 1 and 25 members. No queue model, queue instructions, to-do table/tool or model-written summary remains; seeding explicitly drops the retired table.
- Separate pristine evaluation sources and handler labels. Only backend evaluation code joins expected labels; claim reads/tools and the agent service never request comparisons. Score formulas use inclusive $1 accuracy, lab mistake costs, referrals for missing answers and all selected claims as denominator, including unstarted/stopped copies.
- Dashboard starts, live member progress/totals, Scoreboard list and linked comparisons. Every measure, set/size/N/model/effort/date/status is shown. Missing decisions and misses have text labels. Copied claims are labeled and held copies have no sign-off form.

## Known limits

- Claim reservations are process-local. Do not run a CLI claim concurrently with service work on the same claim; backend decisions/payments still have transactional protection.
- A manually approved claim with no saved graph state cannot resume payment automatically. Normal graph/restart paths save the required state.
- LangGraph 1.2.12 rethrows handled parallel futures on exit (upstream issue 8277). The dispatcher suppresses only the exact recorded handled exception after every selected worker has confirmed completion; unrelated failures still escape.
- Handlers can sign off held payouts; rejection, sign-in, real payments and customer messages are outside this build. No AWS resources were created or deleted.
